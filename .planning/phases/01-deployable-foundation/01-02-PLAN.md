<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pull-request code to GitHub Actions runner | Untrusted changes execute quality commands in an ephemeral runner. |
| CI runner to package registries | Dependency resolution and audit data are fetched from public registries. |
| Browser test to Compose service | Browser automation exercises the application over HTTP. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | GitHub Actions workflow actions | high | mitigate | Pin actions to immutable commit SHAs and grant each workflow only the permissions it needs. |
| T-01-05 | Elevation of privilege | pull-request workflow token | high | mitigate | Use read-only default permissions, avoid deployment credentials on pull-request workflows, and separate production deployment configuration. |
| T-01-06 | Information disclosure | Playwright reports and artifacts | medium | mitigate | Use generated non-sensitive probe data, retain artifacts on failure only, and never record production environment values. |
| T-01-SC | Tampering | Python package installs | high | mitigate | Enforce `uv lock --check`-equivalent validation, `pip-audit`, Dependabot, and the verified package list from `01-RESEARCH.md`. |
</threat_model>
