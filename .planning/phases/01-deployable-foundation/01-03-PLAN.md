<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Render edge to Nginx | Public HTTP/WebSocket traffic is forwarded to the service's only public port. |
| Nginx to Reflex backend | Proxy routes carry browser event traffic to a private backend process. |
| Render service to PostgreSQL | Production connection string grants database access. |
| Application to Sentry | Exception metadata leaves the application to an external monitoring service. |
| Main branch to Render deploy | A repository merge triggers a production deployment. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-07 | Spoofing | reverse proxy request headers | medium | mitigate | Accept only proxy headers set by the Render edge and configure forwarded host/proto handling explicitly in the production process. |
| T-01-08 | Information disclosure | Sentry event capture | high | mitigate | Enable Sentry only by DSN, use default PII scrubbing, avoid customer-data tags, and document DSN storage as a protected Render secret. |
| T-01-09 | Denial of service | public health endpoint | medium | mitigate | Keep readiness checks bounded and free of expensive application work; Render uses it for rollout gating. |
| T-01-10 | Tampering | automatic production deploy | high | mitigate | Limit deployments to main, require the Plan 01-02 GitHub checks before merge, and document rollback through Render deployment history. |
| T-01-SC | Tampering | production package image | high | mitigate | Build from uv-locked packages previously audited in CI; do not install runtime packages outside the lock. |
</threat_model>
