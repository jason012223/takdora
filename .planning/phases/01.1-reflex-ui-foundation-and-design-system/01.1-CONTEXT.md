# Phase 01.1: Reflex UI Foundation and Design System - Context

**Gathered:** 2026-08-22
**Status:** Ready for planning
**Mode:** User-approved autonomous completion

<domain>
## Phase Boundary

Replace the initial Django/HTMX/Bootstrap direction with a Reflex-based application and establish the reusable UI foundation used by every owner, public-booking, and marketing surface. This phase provides design-system and application-shell primitives; it does not deliver a complete business workflow.

</domain>

<decisions>
## Implementation Decisions

- **D-01:** Build Takdora with Reflex so the complete application remains Python-first while the browser UI compiles to React.
- **D-02:** Use Reflex's Radix-based core components as the accessible component foundation. Do not introduce the React-only shadcn/ui package into the Reflex application.
- **D-03:** Create a coherent Takdora theme and shared primitives for navigation, form controls, feedback, status, cards, tables, dialogs, calendars, and responsive layouts before feature-specific screens are built.
- **D-04:** Build visual surfaces code-first and refine them from real rendered screens; do not depend on a local image-generation installation.
- **D-05:** Original generated visuals may support marketing pages, but product claims must use real screenshots or clearly labelled synthetic demo data. Never invent testimonials, customers, benchmarks, or compliance claims.
- **D-06:** Exact visual direction, color system, typography, illustration treatment, and motion grammar are at the agent's discretion, subject to Takdora's Philippines-first small-business audience, accessibility, and the requirement to avoid a generic template result.

</decisions>
