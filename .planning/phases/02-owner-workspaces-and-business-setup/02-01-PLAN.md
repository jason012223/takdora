<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to auth events | Untrusted registration, login, reset, and cookie values reach server-side handlers. |
| Auth database to session cookie | A server-issued opaque credential represents one authenticated owner session. |
| Application to SMTP provider | The app transfers destination addresses and one-time links using provider credentials. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Spoofing | session resolution | high | mitigate | Use random opaque session credentials, store only digests, enforce expiry/revocation server-side, and verify on every protected loader/event. |
| T-02-02 | Information disclosure | password and reset flows | high | mitigate | Use scrypt digests, neutral reset-request feedback, hashed one-time tokens, backend-only auth state, and bounded error messages. |
| T-02-03 | Tampering | reset token | high | mitigate | Bind a digested token to one account, expiry, and consumed timestamp; change credentials and revoke sessions in one transaction. |
| T-02-04 | Denial of service | auth mail | medium | mitigate | Keep SMTP delivery outside write transactions and return retryable safe feedback on delivery failure. |
| T-02-SC | Tampering | dependency installation | high | mitigate | Use existing locked dependencies and Python standard-library cryptography primitives; add no unaudited package. |
</threat_model>
