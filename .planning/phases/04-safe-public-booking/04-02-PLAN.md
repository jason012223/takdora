<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous form event to booking command | Contact data, service ID, slot instant, and idempotency key are untrusted input. |
| Booking command to PostgreSQL | Transactional policy validation becomes a durable appointment record. |
| Concurrent public requests | Independent clients contend for the same business capacity. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-05 | Tampering | booking command | high | mitigate | Validate every field server-side, derive business/service from public identifiers, and rerun the authoritative availability check inside a transaction. |
| T-04-06 | Repudiation | retry and duplicate handling | high | mitigate | Persist a business-scoped opaque idempotency key and return the original durable booking result on replay. |
| T-04-07 | Tampering | concurrent slot writes | critical | mitigate | Lock scheduling authority, use a short transaction, and enforce a PostgreSQL GiST exclusion constraint over half-open UTC periods. |
| T-04-08 | Denial of service | anonymous booking submission | medium | mitigate | Bound payload/key sizes, reject invalid state before database work, and use a honeypot without a dependency or an extra customer step. |
| T-04-SC | Tampering | dependency installation | high | mitigate | Reuse PostgreSQL, SQLAlchemy already supplied by Reflex, and Alembic; no package is installed. |
</threat_model>
