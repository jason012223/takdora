| Boundary | Description |

| Owner action form to lifecycle command | Booking ID, optional message, and confirmation event originate in the browser. |
| Booking transaction to internal audit and outbox | State, support evidence, and customer communication are created after an authorized command. |
| Outbox to customer email | Saved contact and appointment data leave the application through the configured mail boundary. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-05 | Repudiation | booking operation audit | high | mitigate | Persist immutable action, actor, prior/new state, and timestamp inside the accepted lifecycle transaction. |
| T-05-06 | Information disclosure | cancellation email | medium | mitigate | Render only saved customer-safe appointment fields and bounded optional owner message through a dedicated outbox type. |
| T-05-07 | Denial of service | repeated cancellation event | medium | mitigate | Make state transition and notification identity idempotent; reject invalid repeats with typed outcomes. |
| T-05-SC | Tampering | dependency installation | high | mitigate | Extend existing SQLModel and mailer/outbox code; no package installation is planned. |
</threat_model>
