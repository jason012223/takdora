<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Owner payment/email controls to invoice commands | Received total, invoice ID, and optional send instruction are browser-originated. |
| Committed invoice state to notification outbox | Financial state becomes a later external email delivery request. |
| Server-held PDF bytes to SMTP | Private invoice content is sent only to the stored customer recipient after authorization. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-08 | Tampering | received-total command | high | mitigate | Authorize invoice by owner-derived business, parse Decimal server-side, bound it to the frozen total, and recompute state/balance atomically. |
| T-06-09 | Information disclosure | invoice list and payment state | high | mitigate | Scope every list/detail command to the active business and return no foreign result. |
| T-06-10 | Information disclosure | PDF email | high | mitigate | Use only frozen server-held PDF bytes and the snapshot customer recipient; never expose public links, browser recipients, or storage credentials. |
| T-06-11 | Repudiation | message delivery | medium | mitigate | Persist one idempotent outbox identity, attempts, outcome, and bounded error after a committed action. |
| T-06-SC | Tampering | dependency installation | high | mitigate | Reuse existing SMTP and outbox infrastructure; no additional package is installed. |
</threat_model>
